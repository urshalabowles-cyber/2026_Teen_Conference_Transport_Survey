**Email 1 — "Your Revenue Agent Template (it's inside)"**
Deliver the file; give the 4-step run instruction; set the expectation that it's a
production tool, not a tutorial, and that "off" output is the gap, not a bug. *CTA:
Download the template.*

**Email 2 — "The template ran. Now what?"**

**Email 3 — "This is not about Claude"**

workshop.*

**Email 4 — "She ran it. Here's what came out."**

"someday" crowd — go run the template first). *CTA: Join Come Build With Me — $27/mo.*

## What to Remove Because It Feels Generic

- **Any "here are 10 AI tools" energy.** The tool must be invisible within ~3 minutes; the
  system is the star. Tool-explanation time is the #1 churn risk.
- **The hedged triple CTA** ("template OR workshop OR offer"). One next step. The rest is
  the ladder, not the ask.
- **Trying to build all five outputs fully on screen.** Reads rushed or fake. Two live,
  three as real template outputs.
- **A vague "$27, link in bio" CTA.** Name the specific gap the template doesn't fill and
  give the session specifics. Precision converts this audience; enthusiasm doesn't.
- **"AI will save you time" filler, fake examples, and any condescension.** Ronnie has a
  degree and a career. She's new to LLMs, not to work. Condescension is a skip trigger.
- **A generic workshop landing page** (stock photos, "join our community"). It breaks the
  premium signal the video and emails establish. The page must be as direct as the emails.

## Open Risks / Friction (carry into the build checklist)

- **Setup barrier is the highest-risk friction point:** Claude Code install + API key +
  project directory will lose a chunk of downloaders unless the README walks it in plain
  language. Cannot assume she knows what a project directory is.
- **Thin first-run output** may read as "broken" rather than "needs judgment" — Email 1
  pre-empts this.
- **$27 → $2,500 jump** relies on the workshop surfacing premium buyers; the session design
  must explicitly name what the done-with-you build is and who it's for.
- **Social proof lives almost entirely in Email 4** — consider seeding one specific result
  in Email 1 so the frame is set from the first touch.
